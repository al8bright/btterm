# 서버 상태 줄 (2026-10-20)

사용자 요청: "각 연결 창별로 하단에 그 접속 서버의 기본적인 모니터링이 보여져야 한다. os, cpu, ram, 네트워크(업로드, 다운로드), 켜진 실행일, 로그인 아이디, 하드용량 등. 창 크기에 맞게 제한되어 나오고, 작아지면 스크롤바 대신 좌우 버튼."
PRD에 없던 기능이라 F3.18(M1)·AC34로 추가한다.

| # | 상황 | 결정 | 근거 |
|---|---|---|---|
| ST1 | 수집 방법 | 같은 SSH 연결에 exec 채널을 열어 **고정 스크립트**(읽기 전용 `cat /proc/...`, `id -un`, `df -kP /`)를 실행하고 표준 출력만 받는다. 사용자·원격 입력을 명령에 넣지 않는다 | 에이전트 설치 없이 MobaXterm 모니터링 바와 같은 정보. 명령 주입 표면 없음 |
| ST2 | 주기·범위 | 3초, renderer가 **보이는 칸의 ready 세션**만 요청. 한 세션에 동시에 하나만 | 원격 부하·채널 수 최소화 |
| ST3 | 계산 위치 | 원문 해석·CPU%·네트워크 속도(이전 표본과의 차이)는 core 순수 함수, 이전 표본은 session host의 HostSession이 보관 | 결정적 단위 테스트(AGENTS §3) |
| ST4 | 경계 | renderer → main `stats.read` → host `readStats` → `statsResult`. 결과는 길이 제한 스키마(문자열 상한), renderer는 텍스트로만 표시 | SEC-1(비밀 없음), SEC-5(원격 내용 불신) |
| ST5 | 상한 | 스크립트 출력 64KB, 5초 시간 초과 시 이번 회차는 건너뜀 | 느린 서버에서 채널 누적 방지 |
| ST6 | 비 Linux | `/proc`가 없으면 OS(`uname -s`)·아이디·디스크만, 나머지 "—" | 범위 최소화 |
| ST7 | 저장 | 표본은 메모리에만, 디스크·로그에 남기지 않음 | 개인정보·SEC-4 |
| ST8 | 원격 영향(보안 리뷰 #2) | exec는 사용자 로그인 셸의 `-c`로 실행되므로 셸 rc의 부작용, `ForceCommand`·`command=` 강제 명령, 감사 로그(auditd·snoopy) 기록이 생길 수 있다. 완화: 최소 간격 2초, 표지 없는 출력·실패 3회 연속이면 그 세션 수집 중지, 창이 가려지면 조회 중지. 프로필별 끄기·production 기본 OFF는 ST10 | 보안 리뷰 |
| ST9 | 명령 타입(보안 리뷰 #3) | `execCapture`는 `FixedCommand`만 받는다. 만드는 곳은 core 상수 `STATS_SCRIPT`뿐 | 주입 방지를 타입으로 강제 |
| ST10 | 서버별 끄기(사용자 결정, 같은 날) | `HostDefaults.serverStats`(선택, 그룹 상속). 값이 없으면 `production`·`prod` 태그 서버는 끔, 빠른 연결은 켬. 선택 항목 추가라 기존 파일이 그대로 유효해 스키마 버전은 올리지 않는다(올리면 이전 앱이 새 파일을 거부) | 보안 리뷰 #2 후속 |
