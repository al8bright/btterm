# 탭 드래그 분할 M1 이동 (2026-10-20)

사용자 요청: "2개 이상의 서버를 연결했다면 탭을 마우스 드래그로 분할할 수 있어야 한다."
PRD는 분할 화면을 M2(F3.10, PLAN 2-B)로 두었다. 기본 분할만 M1로 옮기고(F3.10a), 저장·복원·크기 조절은 M2에 남긴다.

## 결정

| # | 상황 | 결정 | 근거 |
|---|---|---|---|
| SV1 | 범위 | **F3.10a 탭 드래그 분할(M1)**: 한 방향 균등 분할, 최대 4칸, 분할 그룹 1개. Workspace 템플릿·칸 크기 조절·격자 분할은 F3.10(M2) | 요청 핵심(끌어서 나란히 보기)만 먼저. 트리 레이아웃은 저장·복원과 함께 설계 |
| SV2 | 상태 위치 | 분할 레이아웃은 `AppStore`(UI 상태), 배치 계산은 순수 함수 `workspace/groupLayout.ts`(SV8 이후) | 터미널 바이트·xterm 소유는 그대로 `TerminalRegistry`(AGENTS §3) |
| SV3 | 화면 배치 | 칸 = 탭바 + 본문(flex). 칸 안 터미널은 숨김만 하고, 다른 칸으로 옮길 때만 레지스트리가 소유한 요소를 새 자리에 다시 붙인다(엔진·버퍼 유지) | 탭 전환 때 버퍼·포커스 보존 |
| SV4 | WebGL | 보이는 터미널마다 켠다(최대 8, SV10). LRU 풀은 M2 | Chromium WebGL 컨텍스트 상한(16) 안 |
| SV5 | 활성 | 칸을 클릭·포커스하면 그 탭이 활성. `data-active`는 활성(키 입력 대상), `data-visible`은 보임 | 기존 E2E 선택자 유지 |
| SV6 | 끌기 | HTML5 드래그. 끄는 탭 id는 store에 두고, 놓을 쪽은 포인터에 가장 가까운 허용된 가장자리 | 프로세스 경계를 넘지 않는 renderer 내부 동작(새 IPC 없음) |
| SV8 | 칸별 탭 (사용자 결정, 같은 날) | "탭도 분할된 창 위에 있어야 한다" → 두 안 중 **칸마다 탭 그룹(VS Code식)** 선택. 위쪽 전체 탭바를 없애고 칸마다 탭바. SV1의 "분할 그룹 1개·칸=세션 1개" 모델을 **칸 = 탭 묶음** 모델(`GroupLayout`)로 대체 | 사용자 선택(AskUserQuestion) |
| SV9 | 칸 옮기기 | 칸 가운데·다른 칸 탭바에 놓으면 그 칸으로 옮긴다. 빈 칸은 즉시 제거 | VS Code 관례 |
| SV10 | 중첩 분할 (사용자 요청, 같은 날) | "처음 좌우나 상하로 분할되어 있어도 그 이후 분할된 창에서 좌우 상하 어디로든 분할" → 배치를 한 방향 칸 목록에서 **분할 나무**(묶음 = 방향 + 자식들, 잎 = 칸)로 바꾼다. 최대 칸 수 4 → 8(보이는 터미널마다 WebGL, Chromium 컨텍스트 상한 16 안) | 사용자 요청 |
| SV7 | 탭 순서 | 탭을 다른 탭 위에 놓으면 그 자리로 이동(DESIGN §8.2 "드래그 = 순서 변경") | 같은 끌기 동작과 일관 |
